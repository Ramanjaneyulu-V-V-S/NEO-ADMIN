1 Overview

The Create User wizard provisions a complete user account in the NABARD Documentum system. A single form submission triggers up to four backend operations in sequence:

1

Create dm_user

Documentum Content Server
Object: dm_user

2

Provision OTDS Account

OpenText Directory Services
OTDS user + partition membership

OTDS source only
3

Create User Profile

Content Server
Object: cms_user_profile

4

Add to Superusers Group

Content Server
Group: dm_superusers_dynamic

⚠

If Step 1 fails, all subsequent steps are skipped. If Steps 2–4 fail, the dm_user object is not rolled back — a warning is displayed instead.

2 Prerequisites

  • You must be logged in to the NB Support App with a support-team account.
  • The Documentum Content Server and OTDS server must be reachable from the backend.
  • For OTDS-sourced users, the target OTDS partition (default: DCTMPartitions) must already exist in OTDS Admin.

4 Step 1 — Identity

Captures the user's display name, login credentials, and contact information.

Fields

Field (Attribute) Required Notes
user_name Required Display Name. Full name as it will appear in Documentum. This is the object identifier used in Documentum REST API paths (e.g. /users/{user_name}). Case-sensitive.
user_login_name Required Login Name. The login ID the user types at the Documentum login prompt. Must be unique across the repository.
user_address Optional Email Address. Used during OTDS account creation and for notifications.
description Optional Description. Free-text note about the user stored on the dm_user object.

Hindi Auto-fill

When you type in Display Name, the Hindi Name field in Step 3 is pre-filled automatically. You can override it by typing directly in that field — auto-fill stops once you have manually edited it.

Validation

Display Name and Login Name are both required before you can proceed to Step 2. Whitespace-only values are rejected.

5 Step 2 — Authentication

Captures the user's authentication source and, depending on the source, the initial password.

User Source

Source Description
OTDS Default User is authenticated via OpenText Directory Services. An OTDS account is created and added to the DCTMPartitions partition during provisioning.
inline password Local Password is stored directly in Documentum (no OTDS). Suitable for service or system accounts.
LDAP LDAP User is sourced from an external LDAP directory. No password is set here — LDAP handles authentication.

OTDS Source — Additional Fields

When OTDS is selected, an expanded panel appears with the following fields:

Field Required Notes
otds_password Required Initial OTDS Password. Minimum 8 characters. Set in OTDS, not in Documentum.
otds_confirm_pw Required Confirm Password. Must exactly match the Initial OTDS Password.
otds_partition Required OTDS Partition. Name of the OTDS partition to add the user to. Default: DCTMPartitions. Change only if the target partition differs.
otds_no_reset — Do not require password change on reset. Checkbox, checked by default. When checked, the user is not forced to change the password at first login. Uncheck to force a password change on first login.

Inline Password Source — Additional Field

Field Required Notes
user_password Optional Direct password stored in Documentum. If left blank, the account is created without a password (not recommended).

Advanced Settings

Click Advanced (collapsed by default) to reveal optional Documentum technical fields:

Field (Attribute) Default Notes
user_os_name—OS-level username (for OS-authenticated repositories).
user_db_name—Database-level username.
user_global_unique_id—Globally unique identifier used in federated environments.
default_folder—Path to the user's home cabinet (e.g. /NABARD/Users/john).

6 Step 3 — Profile

Captures the user's NABARD organisational profile, stored as a cms_user_profile object in Documentum.

Fields

Field (Attribute) Required Notes
profile_designation Required Job title in English (e.g. "Deputy General Manager").
profile_hindi_designation Optional Job title in Hindi script. Auto-filled from English designation if not manually edited.
profile_hindi_user_name Optional User's name in Hindi script. Auto-filled from Display Name (Step 1) if not manually edited.
profile_uin Optional Unique Identification Number assigned by NABARD.
profile_office_type Required Office Type. HO (Head Office), RO (Regional Office), or TE (Training Establishment). Drives the Location and Department dropdowns.
profile_location Required Location. Constrained by Office Type. HO is fixed to Mumbai (disabled). RO shows 31 locations; TE shows 4 locations.
profile_ro_short_code Auto RO/TE Short Code. Read-only. Auto-filled when Location is selected.
profile_department_name Required Department Name. Constrained by Office Type and Location.
profile_department_short_code Auto Department Short Code. Read-only. Auto-filled when Department is selected.
profile_user_grade Required Grade classification value (e.g. grade_a). See grade table below.
profile_grade_level Required Numeric grade level 0–6. 0 is a valid value (Group B).
profile_is_active — Toggle. Default: Active (true). Set to Inactive if the profile should be disabled.

7 Submission and Backend Operations

Operation 1 — Create dm_user

Endpoint: POST /api/users

The backend creates a dm_user object in the Documentum repository:

POST  {dctm.rest.url}/repositories/{repository}/objects
Content-Type: application/vnd.emc.documentum+json

Body — key attributes:
  user_name           → Step 1 Display Name
  user_login_name     → Step 1 Login Name
  user_address        → Step 1 Email
  user_source         → Step 2 User Source
  user_password       → Step 2 (Inline Password only)
  user_privileges     → Step 2 Advanced
  user_state          → Step 2 Advanced
  description         → Step 1 Description
✓

On success: the r_object_id of the new dm_user is returned and used in subsequent steps.

✗

On failure: an error toast is displayed. Provisioning stops — no further operations are attempted.

Operation 2 — OTDS Provisioning OTDS source only

Endpoint: POST /api/users/otds/setup

Three OTDS REST API calls are made in sequence:

2a. Create OTDS User

POST  {otds.url}/users
Body: {
  "userIdentifier": "<loginName>",
  "displayName":    "<displayName>",
  "email":          "<email>"
}

2b. Add User to OTDS Partition

POST  {otds.url}/partitions/{partitionName}/members
Body: { "userIdentifier": "<loginName>" }
Default partition: DCTMPartitions
This grants access to Documentum via OTDS single sign-on.

2c. Set Initial Password

PUT   {otds.url}/users/{loginName}/password
Body: {
  "newPassword":            "<password>",
  "requiresPasswordChange": false   // true when "Do not require" is unchecked
}
⚠

On failure: a warning toast is shown: "User created in Documentum but OTDS setup failed." The dm_user is not deleted. OTDS setup must be retried manually via the OTDS Admin console or the /api/users/otds/setup endpoint.

Operation 3 — Create cms_user_profile

Endpoint: POST /api/users/profile

Creates a cms_user_profile object in the Documentum folder /UserProfile/UsersProfileBO with all Step 3 attributes (designation, office type, location, department, grade, etc.).

Operation 4 — Add to dm_superusers_dynamic Group

Immediately after dm_user creation succeeds, the backend automatically adds the new user to the dm_superusers_dynamic Documentum group:

POST  {dctm.rest.url}/repositories/{repository}/groups/dm_superusers_dynamic/users
Body: {
  "href": "{dctm.rest.url}/repositories/{repository}/users/{user_name}"
}
NOTE: {user_name} = Display Name from Step 1 (the dm_user object identifier).
Documentum REST paths are case-sensitive and resolve by user_name, NOT user_login_name.
ℹ

If the group membership call fails, a warning is logged server-side but provisioning continues. The dm_user and cms_user_profile are still created successfully.

10 Cascading Dropdown Behaviour

The Office Type, Location, and Department fields are linked. Changing a parent clears all child selections.

  • Location is disabled and fixed to Mumbai — cannot be changed.
  • RO/TE Short Code is hidden/disabled for HO.
  • Department shows all 41 Head Office departments.

  • Location dropdown lists all 31 Regional Office locations.
  • On selecting a location, RO/TE Short Code is auto-filled.

  • Location dropdown lists 4 Training Establishment locations.
  • On selecting a location, RO/TE Short Code is auto-filled.
  • Department shows departments for the selected TE location.

12 Common Errors and Fixes

⚠ User created in Documentum but OTDS setup failed
Cause: OTDS server unreachable; the OTDS partition does not exist; or the login name is already taken in OTDS.
Fix:
  1. Verify the OTDS server is running at {otds.url}/users.
  2. Confirm the partition name is correct in OTDS Admin.
  3. Retry OTDS setup via POST /api/users/otds/setup or use the OTDS Admin console to create and configure the user manually.
⚠ Failed to add user to dm_superusers_dynamic
Cause: The user_name could not be resolved in the Documentum REST API (case-sensitivity issue), or the group does not exist.
Fix:
  1. Verify the dm_superusers_dynamic group exists in the repository.
  2. Check backend logs for the exact error ([Group] Failed to add user...).
  3. Add the user manually via DQL:
    EXECUTE ADD_USER_TO_GROUP WITH user_name = '<user_name>', group_name = 'dm_superusers_dynamic'
⚠ Grade Level "0" appears invalid / Create button stays disabled
Cause: Older versions of the application treated grade level 0 as an empty value due to a JavaScript falsy check.
Fix: Ensure you are on the latest version of the application, which correctly treats 0 as a valid grade level for Group B.
⚠ Location dropdown shows no options
Cause: Office Type has not been selected yet, or HO was selected (HO has no location dropdown — Mumbai is fixed).
Fix: Select RO or TE as the Office Type first. The Location dropdown will populate with the appropriate locations.
⚠ Department dropdown shows "Select location first"
Cause: Office Type is RO or TE but no Location has been chosen yet.
Fix: Select a location from the Location dropdown. The department list will populate automatically based on the selected location.
