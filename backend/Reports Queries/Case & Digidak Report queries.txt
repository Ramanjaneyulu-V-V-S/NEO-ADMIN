================================================================================
FILTER DETAILS:
================================================================================

OFFICE TYPE (hoRo):
  - Values: 'HO' (Head Office), 'RO' (Regional Office), 'TE' (Telecom)
  - Always required for filtering cases by office

LOCATION:
  - Used only for RO and TE office types
  - Examples: 'Tamilnadu', 'Karnataka', 'Maharashtra', 'Delhi'
  - Full location name (not shortcode)

DEPARTMENT (deptNames):
  - Comma-separated list of department names: 'Finance', 'HR', 'DDSI', 'Operations'
  - Supports multi-department filtering
  - Format in query: department_name IN ('dept1', 'dept2', ...)

VERTICAL (functions):
  - Only applicable for HO office type with selected department
  - Examples: 'Digital Transformation Vertical', 'Business Process Engineering Vertical'
  - Matches cms_case_folder's functions attribute

DATE RANGE:
  - fromDate: Minimum creation date (ISO format: 'yyyy-mm-dd')
  - toDate: Maximum creation date (ISO format: 'yyyy-mm-dd')
  - Filter: r_creation_date >= DATE('<date>', 'yyyy-mm-dd')
  - Filter: r_creation_date <= DATE('<date>', 'yyyy-mm-dd')

STATUS:
  - Values: 'In-Progress', 'Approved', 'Closed', 'Cancelled'
  - Always excludes: 'Delete', 'Draft'

PRIORITY (task_priority):
  - Values: 'Ordinary', 'Urgent'

LANGUAGE (language_type):
  - Values: 'Bilingual', 'English', 'Hindi', 'Others'

PAGINATION:
  - ENABLE(RETURN_TOP <count>)
  - count = page_number * itemsPerPage (default itemsPerPage = 10)
  - Page 1: RETURN_TOP 10 (items 1-10)
  - Page 2: RETURN_TOP 20 (items 1-20, client takes 11-20)
  - Page 3: RETURN_TOP 30 (items 1-30, client takes 21-30)

================================================================================
KEY NOTES:
================================================================================

1. All queries ALWAYS exclude:
   - is_migrated = TRUE (or IS NOT NULL and TRUE)
   - status = 'Delete'
   - status = 'Draft'

2. Location filter uses FULL location name, not shortcode:
   ✓ Correct: location = 'Tamilnadu'
   ✗ Wrong:   UPPER(object_name) LIKE '%-TN-%'

3. Vertical (functions) filter:
   - Only available for HO office type
   - Requires a specific department to be selected first
   - Uses object_name from dm_group (vertical group)

4. No default date range:
   - Unlike searchCases, getCasesReport does NOT apply default months window
   - User must explicitly set From Date / To Date

5. Multi-department support:
   - Applies to all office types (HO, RO, TE)
   - Single department: department_name IN ('Finance')
   - Multiple departments: department_name IN ('Finance', 'HR', 'Operations')

DIGIDAK FILTER DETAILS:
================================================================================

OFFICE TYPE (hoRo):
  - Values: 'HO' (Head Office), 'RO' (Regional Office), 'TE' (Telecom)
  - Always required for filtering digidak

LOCATION:
  - Used only for RO and TE office types in Outbox
  - Examples: 'Tamilnadu' (tn), 'Karnataka' (ka), 'Maharashtra' (mh)
  - Location shortcode is used in login_cgm_group pattern

DEPARTMENT (deptNames):
  - Used only for HO office type in Outbox
  - Examples: 'DDSI', 'Finance', 'HR'
  - Department shortcode is used in login_cgm_group pattern
  - Pattern: ecm_digidak_ho_<dept_shortcode>_cgm

SOURCE VERTICAL:
  - Only applicable for Outbox report with HO or RO/TE + Location
  - Filters cms_digidak_folder's source_vertical attribute
  - Values come from dm_group group_display_name where:
    * For HO: group_name LIKE 'ecm_ho_<dept_shortcode>_%'
    * For RO/TE: group_name LIKE 'ecm_<location_shortcode>_%'
  - Excludes: 'dm%', '%_grade_%', '%vertical_head%', '%cgm_sec%'

INBOX FILTERS (decision = 'Inward'):
  - Username required (not shown in WHERE clause)
  - Uses two-step DQL: username → group names → filter folders
  - Department and Location optional (HO, RO, TE all supported)

OUTBOX FILTERS (decision = 'Outward'):
  - Department required for HO
  - Location required for RO/TE
  - Source Vertical optional
  - Date Range optional

DATE RANGE:
  - fromDate: Minimum creation date (ISO format: 'yyyy-mm-dd')
  - toDate: Maximum creation date (ISO format: 'yyyy-mm-dd')
  - Format: r_creation_date >= DATE('<date>', 'yyyy-mm-dd') AND r_creation_date <= DATE('<date>', 'yyyy-mm-dd')+1

DECISION (Inbox vs Outbox):
  - Inbox: decision = 'Inward'
  - Outbox: decision = 'Outward'

LANGUAGE (languages):
  - Values: 'English', 'Hindi', 'Bilingual', etc.

PRIORITY (priority):
  - Values: 'Ordinary', 'Urgent', etc.

SECRECY (secrecy):
  - Values: 'Confidential', 'Secret', 'Top Secret', etc.

STATUS (status):
  - Common values: 'Unread', 'Opened', 'Assigned', 'Closed', 'Responded'
  - Always includes 10 mandatory status values (see MANDATORY FILTERS)

TYPE CATEGORY (type_category):
  - Examples: 'Actionable', 'For Information', 'For Approval'

PAGINATION:
  - ENABLE(RETURN_TOP <count>)
  - count = page_number * itemsPerPage (default itemsPerPage = 10)
  - Page 1: RETURN_TOP 10 (items 1-10)
  - Page 2: RETURN_TOP 20 (items 1-20, client takes 11-20)

KEY NOTES (DIGIDAK):
================================================================================

1. All Digidak queries ALWAYS include mandatory filters:
   - is_ddm = false
   - is_endorsed_letter = FALSE
   - is_migrated = false
   - 10 status values (see MANDATORY FILTERS)

2. INBOX vs OUTBOX differences:
   INBOX (Inward):
     - Requires username filter (two-step DQL query)
     - Department/Location optional (used only if selected)
     - No Source Vertical filter

   OUTBOX (Outward):
     - Requires Department (HO) or Location (RO/TE)
     - Source Vertical available as optional filter
     - Username not used

3. login_cgm_group pattern (based on office type):
   - HO:  ecm_digidak_ho_<dept_shortcode>_cgm
         Example: ecm_digidak_ho_ddsi_cgm
   - RO:  ecm_digidak_ro_<location_shortcode>_cgm
         Example: ecm_digidak_ro_tn_cgm (Tamil Nadu)
   - TE:  ecm_digidak_te_<location_shortcode>_cgm
         Example: ecm_digidak_te_ka_cgm (Karnataka)

4. Source Vertical Lookup DQL:
   For HO with Department:
     SELECT group_display_name FROM dm_group
     WHERE group_name LIKE 'ecm_ho_<dept_shortcode>_%'
       AND group_name NOT LIKE 'dm%'
       AND group_name NOT LIKE '%_grade_%'
       AND group_name NOT LIKE '%vertical_head%'
       AND group_name NOT LIKE '%cgm_sec%'

   For RO/TE with Location:
     SELECT group_display_name FROM dm_group
     WHERE group_name LIKE 'ecm_<location_shortcode>_%'
       AND group_name NOT LIKE 'dm%'
       AND group_name NOT LIKE '%_grade_%'
       AND group_name NOT LIKE '%vertical_head%'
       AND group_name NOT LIKE '%cgm_sec%'

5. Movement Register (cms_digidak_movement_re):
   - Separate object type from main digidak_folder
   - Linked via i_folder_id = digidak's r_object_id
   - Returns: Type Category, Letter Subject, Performer, Status, Assigned User, Entry Type, Received Date, Completed Date

6. DISTINCT keyword:
   - Used in SELECT to avoid duplicate records
   - Important when multiple filters applied
